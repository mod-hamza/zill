- `agent/llm.py`: `LLMClient` over `openai.OpenAI(base_url, api_key)`; `available()` = key present AND `GET /models` succeeds within 4 s (cache 60 s); model fallback list per CONTRACTS §1; tool calling via `tools=[{"type":"function","function":{name,description,parameters}}]`, parse `message.tool_calls`; robust to providers that return tool args as strings; retries ×2 with backoff; per-call timeout 30 s. ## Build
1. `tools.py`: every tool in PRD §11.6 with JSON schema, deterministic, returns `{ok, data, summary}`; per-tool timeout 8 s (thread), ≤ 12 calls/turn, errors as data. Each tool result stored in a per-session **result store** under a stable key (e.g. `route`, `departure`, `weather`, `place.origin`) so tokens resolve (`{{route.coolest.sun_saved_min}}`).
2. `tokens.py` (PRD §11.4): resolver with format suffixes `_min` (s→min 1 dp), `_pct`, `_time` (HH:MM Gulf), `_m`, `_km`; path resolution into the store (support derived fields: for any `*_s` field, `*_min` is available). Unresolved token → error list (triggers one retry). Numeric guard: regex rejects bare numbers in model text except: numbers present in the user's own message, clock times/years from the user, ordinal words, list numbering at line start. Fuzz test: ≥ 200 adversarial strings (bare digits, "about 5 minutes", "30%", unicode digits, numbers inside words) must be rejected or rewritten; legitimate token text passes.
3. `prompts.py`: versioned system prompts (`PLANNER_V1`, `VERIFIER_V1`, `NARRATOR_V1` per persona) per PRD §11.4b, including token rules with examples, tool-use guidance, health framing, limits honesty.
4. `orchestrator.py`: session state (`persona, city, date_key, sim clock, autonomy L1/L2/L3, active_plan, pending approval, history, result store`), the Planner tool loop → draft → **Verifier** (separate call + separate system prompt; ALSO a deterministic verifier layer `verifier.py` that checks every token resolves, every numeric claim is tokenised, route edges valid for mode, arrival window, policy pack via ROUTING's `check_policy` if present) → max 2 fix rounds → Narrator → `message{text,resolved}`; emits SSE events of PRD §11.3 with `{id, ts, type, payload}`. `thought` events are short summaries, never raw chain-of-thought. Proposal → approval_request (L2/L3) → `/api/agent/approve` → `plan_committed`.
5. `monitor.py`: simulated clock (×60 default, jumpable), tick re-evaluation of the active plan (re-run route at new departure / with closure (edge blocked) / delay / heat_alert from weather), thresholds; replan → autonomy policy PRD §11.5 (L3 auto-apply if |Δarrival| ≤ 10 min and RHL ≤ +10%, else approval; every autonomous action logged with reason and `undo` token). Deterministic for tests (inject clock).
6. `personas.py`: tourist / rider / crew definitions and narrator tone.
7. `replay.py`: load `backend/replay/*.json`, match free text to a recording via `data/curated/intents.json` (keywords → scenario_id), replay events with original relative timing (speed param), badge field `{"source":"recorded"|"scripted"}`; unmatched → message "This is a recorded session. Connect to the network to chat live."
8. `api/routes_agent.py`: `POST /api/agent/session`, `POST /api/agent/message` (SSE; live if `llm.available()` and not ZILL_REPLAY, else replay), `POST /api/agent/approve`, `POST /api/agent/simulate`, `GET /api/agent/replays` (list). Use `zill.api.sse` helper if present; otherwise write a local helper and note it.
9. `scripts/record_replay.py`: runs the real orchestrator (live model with `--live`, else scripted planner) on the 3 hero scenarios from `data/scenarios/hero.json` (prompts phrased from the real origin/dest names, e.g. "Metro to the Opera, 13:30, I'm walking") + one replan demo (tourist plan committed at L3, then simulated 20-min delay → monitor replan → auto-applied with undo), saving CONTRACTS §7 files. If hero.json isn't there yet, poll for it (up to 60 min, every 2 min) while finishing tests; if still absent, record against two POIs from pois.json and note it.
