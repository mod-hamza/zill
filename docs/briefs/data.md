# Brief: DATA stream — Phase 1, Downtown Dubai bake (PRD §6)

Read: `docs/briefs/common.md`, `docs/CONTRACTS.md` (§2, §3 are your output spec — follow exactly), PRD §5, §6 (all), §7.2 (heightmap consumer), §18.1, §20 Phase 1 gate.

You own: `backend/zill/data/*`, `backend/zill/geo.py` (implement it; scaffold may have left a stub), `data/curated/**`, `data/cities/dubai_downtown/*` EXCEPT `shade/` and `exposure_*.npz`, `backend/tests/test_geo.py`, `backend/tests/test_data_*.py`, `backend/tests/fixtures/overpass_*`.

## Build
1. `geo.py`: `to_local`, `to_wgs84` (vectorised numpy too), constants from config. Golden file `data/curated/geo_golden.json` with 10 points `{lat,lon,x,z}` (frontend test uses it). Test: 1000 random round-trips < 0.01 m.
2. `data/overpass.py`: POST with UA header, timeout 180 s, exponential backoff (5 tries), rotate `OVERPASS_URLS`, tile the bbox 4×4 (caster bbox for buildings, scene bbox for everything else), `out body geom;` style so ways include geometry (use `out geom` + `>;` as needed; relations for multipolygon buildings: `rel["building"]` with `out geom`). Cache every raw response to `data/raw/<city_id>/<sha1(query)>.json`; re-runs must hit the cache. Dedupe by `type/id`.
3. `data/bake.py` (`python -m zill.data.bake --city dubai_downtown [--refresh]`), city config from a small registry `data/cities.json` = `[{city_id,name,bbox(core),origin,timezone}]` — NO city-specific code paths; Dubai extras come from `data/curated/dubai_downtown/` (landmarks.json, ac_links.geojson, entrances.json, gazetteer.json) if present.
   Steps (time each, record into `meta.build_log` with real counts): geocode(origin/bbox) → fetch_buildings → fetch_roads → fetch_trees → heights → graph → covered_links → write. (shadow_precompute is appended later by the shade stream; leave a hook.)
4. Heights per PRD §6.4 exactly (parts replace shells: a shell is dropped when ≥1 `building:part` polygon has its centroid inside it; parse "m"/"ft"/"'" units; min_height; levels×3.4 (+roof:levels×3.0); fallbacks by tag; landmarks.json override). Burj Khalifa: check how OSM models it; final max height of the Burj (shell or tallest part) must be 828 ± 5 m — add `data/curated/dubai_downtown/landmarks.json` override only if OSM is wrong. Test asserts it (skip the test with a clear reason if the baked file is absent).
5. Footprints: shapely; fix invalid with `make_valid`/buffer(0); multipolygon relations → separate polygons with holes; drop < 4 m² slivers; simplify 0.3 m. Project to local metres.
6. `buildings.glb`: earcut-triangulated flat-roof extrusions (walls + roof; skip floor), per 250 m tile, attributes per CONTRACTS §3 (`_BUILDING_ID`, `_HEIGHT` as custom float attributes — glTF requires custom attribute names to start with underscore). Use trimesh or pygltflib; verify the glb loads with trimesh round-trip AND write a tiny `frontend/public/dev/glb-check.html` is NOT yours — instead produce `data/cities/dubai_downtown/glb_report.json` (tiles, vertex/triangle counts, bounds). Keep glb < 40 MB (it'll be fine).
7. Graph per PRD §6.5: walkable/cyclable classes, access/foot/bicycle rules, split ways at shared nodes (node used by ≥2 ways or endpoints), crossings as node flags (`highway=crossing` nodes or `footway=crossing` ways), stairs (`highway=steps`), mode allow flags, largest connected component per mode (walk component is the main graph; keep nodes in union of kept components; log dropped). Geometry in local metres rounded 0.01. Expect > 10,000 edges (gate). If Overpass footways are sparse also include `highway=service|unclassified|corridor|elevator(no)`, footway=sidewalk ways are footways.
8. Covered/indoor/ac_link classification per §6.6. Look for the Burj Khalifa/Dubai Mall Metro link (OSM name likely "Dubai Mall Metro Link"/bridge with `covered=yes`/`indoor`/`layer`). If not tagged, draft `data/curated/dubai_downtown/ac_links.geojson` from OSM geometry found by name with `"verified": false` and snap/insert edges into the graph (as new edges between nearest graph nodes, cls `ac_link`, flagged `curated`). Entrances: `entrance=*` nodes; transitions outdoor↔indoor only at entrance nodes or curated entrances (`entrances.json`); if a mall has none, create conservative curated ones and log it. Add every unverified item to `docs/OPEN_ITEMS.md`.
9. Trees per §6.7 → `trees.json` (scene bbox + caster buffer, since trees cast shade). Note honest under-estimate in `docs/VALIDATION.md` (create a "Data" section; don't delete others' sections).
10. POIs/gazetteer → `pois.json` (CONTRACTS §3): resolve by name via OSM for every PRD §6.2 gazetteer entry + ≥ 14 more real named POIs in the core bbox (hotels, malls, metro, parks, Opera, Souk Al Bahar, Boulevard Plaza, Address Downtown, Armani, Palace Downtown, Vida, Burj Park, Dubai Opera, Emaar Square, Dubai Fountain viewing). Snap each to nearest walk-graph node (record snap distance; warn if > 60 m). Log resolved coordinates in DECISIONS/VALIDATION. These feed the hero scenario search (needs ≥ 12 POIs).
11. `links.geojson`, `building_mask.png` is the SHADE stream's; you write `meta.json` per CONTRACTS §3 (core_grid/caster_grid computed from bboxes with res 2.0, x0/z0 snapped to multiples of 2 m).
12. City-agnosticism test: `tests/test_data_synthetic.py` bakes a tiny synthetic bbox from fixtures in `tests/fixtures/overpass_*.json` (hand-written minimal OSM JSON: 3 buildings incl. one with parts and one with levels, 6 ways, 1 tree, 1 covered way) with network disabled (monkeypatch), asserts outputs and height rules.
13. Bake size target: commit-friendly (< 60 MB for the city folder excluding shade). Use compact JSON (no indent) for large files.
