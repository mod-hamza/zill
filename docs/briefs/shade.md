## Build
1. `sun/position.py`: pvlib `get_solarposition` (Asia/Dubai, UTC+4). `SunPos(alt_deg, az_deg, vector)` with vector = (sin az·cos alt, sin alt, −cos az·cos alt). `sun_times(date)` sunrise/sunset/solar noon. Generate `data/curated/sun_golden.json`: 20 timestamps over the 4 preset dates + 4 others, fields `{ts, lat, lon, alt, az}` (frontend suncalc test compares within 0.5°). Tests: 21 Jun noon alt ≈ 88° (±1), 21 Dec ≈ 41° (±1), vector tests az=90→+x, az=0→−z, sunrise/sunset sanity.
2. `shade/heightmap.py`: rasterise caster grid from buildings.json (all buildings, `max(height)` per cell; respect min_height: a part floating above ground with min_height>h0 still blocks rays passing between min and max — store `Hmin`,`Hmax` grids; for v1 treat blocking if ray height in [Hmin,Hmax]) and tree canopy grids (`canopy_top`, `canopy_bottom`≈ h·0.35, `canopy_block` 0.65 disc of radius r). Building mask on the core grid. Use skimage.draw.polygon or matplotlib Path / numba scanline (add scikit-image if you use it). Respect CONTRACTS §2 orientation: row 0 = north (min z). Unit test the orientation explicitly (a building at x>0,z<0 lands in the NE quadrant: low row, high col).
3. `shade/raymarch.py`: numba `@njit(parallel=True, fastmath=True)` per PRD §7.3: for each core cell march toward the sun along (dx,dz) = (sin az, −cos az) in grid units (col += sin az, row += −cos az because row increases with z (south)), step = res, until MAX_SHADOW_M or ray height > max scene height; buildings fully block; tree canopy multiplies transmission. Soft edges: average 3 sun samples (alt/az ± 0.265° around the disc) — or 5 if it fits the budget. alt ≤ 2° → all 0 + night flag. Output uint8 sun_fraction, building cells = 0. Performance gate: one step on the real Dubai grid ≤ 2.5 s (log your machine timing: 24 cores, RTX 4070 laptop). If slow, switch to the O(N) sweep formulation and log it.
   Required tests (PRD §7.3 a–d): 100 m box at alt 45° → shadow length 100 ± 3 m for az 90/180/270 in the correct direction (az=90 sun in the east → shadow extends WEST: decreasing x); alt 90 → footprint only; two boxes with gap; 90° rotation symmetry.
4. `shade/exposure.py`: per edge (graph.json `geom`), samples every 3 m (≥2), bilinear sample of sun_fraction/255, mean → exposure; covered/indoor/ac_link → 0; samples inside building mask (not indoor) → nearest outdoor value within 3 m (count and log how often). Vectorise all edges at once per step (precompute sample coords once).
5. `shade/cache.py` + `shade/bake.py`: steps every 10 min from (sunrise − 20 min) floored to 10 → (sunset + 20 min) ceil. Write `shade/<date_id>/step_HHMM.png` (Pillow, optimize=True) + `index.json` + `exposure_<date_id>.npz` per CONTRACTS §3 for all 4 preset dates. On-demand dates: `compute_date(city_id, iso_date, progress_cb)` computing the requested step first, caching to `data/cache/<city_id>/<iso>/`, thread-pool friendly; `get_shade_step(city, date_key, hhmm)` and `exposure_for(city, date_key)` (memoised). Also append to meta.build_log a `shadow_precompute` entry ONLY through a separate file `data/cities/<id>/shade/bake_log.json` (meta.json belongs to DATA stream; the API merges them).
6. `explain` helper for the agent (`shade/explain.py`): `casting_building(city, x, z, alt, az) -> {building_id, name, height, distance_m} | None` (march the ray and return first blocking building id — keep a building-id grid alongside heights).
7. Visual sanity: write `docs/qa/phase2/` PNG previews: for `hackathon` 12:00 and 16:00 and `summer` 13:30, render the sun_fraction raster with building footprints overlaid in a different tone + a north arrow + a sun-direction arrow (matplotlib is fine if you add it to dev deps). OPEN these images and check shadows point away from the sun (16:00 sun is in the WSW → shadows fall ENE). Fix any mirrored axis. Describe what you saw in your report.
